# BalloonPredictor v1.5.0

Windows, macOS and Debian now open with an animated balloon and three
connection choices: **Run locally**, **Web server**, and **SSH tunnel**.
Android connects to an existing server. On Android, **Server → Return to
flight** and Android Back return to the same live flight and SSH session.
**Connect again** deliberately starts a new connection.

For a private server, start your VPN first if required. Use the usual SSH
host, username and port, and the BalloonPredictor port on the server (usually
8001). Verify the SSH fingerprint with the operator. The password or
keyboard-interactive prompt appears when requested, and credentials are not
saved. SSH works even when BalloonPredictor only listens on the server's
loopback address. Direct web mode needs a reachable URL. Android saves flight
exports through the phone's file picker; weather processing and downloads
stay on the server.

| Package | Supported systems |
| --- | --- |
| Windows Setup.exe | Windows 10/11 x64 with WebView2 |
| Universal macOS DMG | macOS 15+ on Intel and Apple silicon |
| Android APK | Android 8 (API 26) or newer; remote client |
| Debian DEB | Debian 12 or newer, amd64, with GTK and WebKitGTK |
| Source ZIP | Python 3.12 or newer; includes the server edition |

On Debian, install with `sudo apt install ./BalloonPredictor-1.5.0-Debian-amd64.deb`
and open BalloonPredictor from the application menu. APT installs the desktop
libraries; the engine includes its Python runtime. Windows and Mac installers
keep the earlier packaging: the Setup.exe is unsigned, and the Mac app is
ad hoc signed and not notarized. Sign Android release APKs with the same
private key each time. An older test APK with a different key must be removed
before installing the release APK.

## Data and logs

**Manage Weather → Weather storage & cleanup** shows the active data folder,
configuration and processing log. When running in desktop local mode, enter
another writable data folder there and restart the app to use it. Existing
files stay where they are. For the source/server edition, set `data_dir` in
`config.yml` or `BP_DATA_DIR` in the environment. Remote users see the active
paths; the server operator changes the server configuration. Separately set
`era5_root`, `wrf_root`, or `terrain_dir` for existing archives.

| System | Default data directory |
| --- | --- |
| Linux / Debian | `$XDG_DATA_HOME/balloon-predictor` or `~/.local/share/balloon-predictor` |
| Windows | `%LOCALAPPDATA%\BalloonPredictor\data` |
| macOS | `~/Library/Application Support/BalloonPredictor/data` |

v1.5 job failures identify the stage and write to
`<data folder>/logs/balloon-predictor.log`; unexpected errors show the exact
path and job ID. v1.4 reported server errors in the terminal or service
journal; installed v1.4 desktop builds wrote `BalloonPredictor.log` in their
per-user app folder.

## Flight workspace

- Archive date follows the UTC launch date. Picking an archive date changes
  the day and keeps the UTC time. Unavailable dates no longer show the first
  day in the archive.
- Flight Profile floats above the Map / Details split handle. Ascent-only
  flights dim both descent controls in the same way as landing controls.
- **Sensitivity region** replaces the member dots for each flight with two
  or more successful members. The translucent outline encloses their
  endpoints with a rounded margin at the map scale. Two members make a
  capsule; three form a rounded triangle. The envelope describes the samples,
  not a probability.
- The weather, prediction and NetCDF export tools are included in the
  desktop engine and source edition.

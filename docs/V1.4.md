# BalloonPredictor v1.4

This release updates the interface and window behaviour on top of v1.3. It keeps
physical terrain, operational IFS/GFS, ERA5/WRF, coordinated arrivals, model-box
exports and the existing sonde schema. The dependency lock is unchanged from
v1.3; no animation package, video player, Node build or new Python dependency is
needed to run the application. Python 3.12 is recommended; port 8001 remains the
default. See QUICKSTART.md for installation and environment isolation.

## Consistent panel names

All numbered section prefixes have been removed:

| v1.3 name | v1.4 name | Contents |
|---|---|---|
| Flight Setup | Flight Setup | Launch, weather, ground and balloon controls |
| Trajectory | Trajectory | The workspace containing the independent panels |
| Flight Map | Flight Map | Map and predicted tracks |
| Flight Profile | Flight Details | Launch tabs, metrics, altitude history, schedules, notes and downloads |
| Synthetic Radiosonde | Flight Profile | Skew-T, temperature/dew point and wind profiles |

The workspace toolbar uses **Map**, **Details** and **Profile**. The plot in
Flight Profile is still a simulated model sounding, not an observed radiosonde.
The separate profile page uses the same terminology.

**Data origins** replaces the interface label "provenance". It means the source
model/run/files and how they were processed. Existing machine-readable JSON and
NetCDF metadata keys stay compatible; this wording change does not rename API
fields or discard source information. See API-AND-ORIGINS.md for the API and
OpenAPI explanations.

## Sidebar controls

**‹ Controls** is inside Flight Setup, at the right of its heading before the
scrollbar. That heading row remains available when scrolling the setup. Hiding
the sidebar exposes **› Controls** at the left of the Trajectory toolbar, like a
small tab at the workspace edge. The button restores the sidebar without an
extra trip to the page header.

On phones and short touch-screen landscape layouts, the same tab opens the left
drawer. Close it from its own Controls button, the backdrop or Escape. The
visible controls receive focus; the hidden sidebar is inert. Only one main
panel is shown at a time on narrow screens. Calculation status and the balloon
loader remain visible in the workspace when the sidebar is hidden.

## Clearer ground controls

The option now reads **If the balloon is below the model's lowest air level**:

- **Estimate the missing near-surface air**: hold the nearest available wind and
  humidity and estimate temperature/pressure below the lowest usable air anchor.
  This is v1.3's existing approximation, with the same 3 km limit and recorded
  approximation metadata. It does not move your launch or modify model heights.
- **Stop when near-surface model data is missing**: fail instead of using that
  lower-atmosphere approximation.

The explanatory text describes why coarse model terrain can cause the mismatch.
Physical launch-ground checks remain separate. Landing surface and fixed landing
altitude are greyed out and disabled for ascent-only flights and coordinated
arrivals, alongside descent settings. A fixed landing altitude above an
ascent-only target no longer blocks an otherwise valid ascent request. Full
flights still validate landing altitude normally.

All expandable sections show **+** when closed and **−** when open. A plus is
never rotated into a cross. Actual dismiss/minimise controls remain separate.

## Orange balloon while calculating

A small orange vector balloon floats, with a swaying tether and drifting clouds,
beside the real calculation status. The supplied animation was used as a visual
reference; the built-in vector artwork matches the logo/button colour and needs
no external media download. It starts when calculating, continues during job
polling, and stops on success, rejection or failure. It does not imply a made-up
percentage. Users requesting reduced motion get a still balloon and the same
status text.

## Two separate NetCDF download cards

Below the flight metrics/altitude history in Flight Details:

- **Model box NetCDF** has its own **Flights to include** and **Track section**
  options, a teal action button, progress and a teal save link. The flight choice
  applies only to this model box, including successful sensitivity tracks or the
  whole series/coordinated plan as selected. All available model levels and time
  brackets are kept, with v1.3's margin/clipping rules.
- **Sonde NetCDF** has its own **Track section** option, an orange action button,
  progress and an orange save link. It always samples the selected flight only.

Both actions prepare the file in a background job, start the download when it is
ready and leave an explicit **Save filename… ↓** link for downloading again.
Depending on browser settings, the browser may save automatically or show a save
prompt. No default blue/visited-purple download links are used in these cards.
Generated sonde files now persist with the other exports until you clear saved
predictions/exports in Manage weather.

Changing launch or scope displays only downloads belonging to that selection.
If you switch flights during preparation, the old file is kept for its original
selection; it is not shown as the new flight's result and does not auto-download
under the new selection. Reselect the original flight/scope to retrieve its link.
Whole-plan model exports remain the same when switching launches within that
plan. Failed exports display an error and allow retry without disturbing the
other export card.

New API: `POST /api/predictions/{job_id}/sonde-export` accepts `flight_index`
(default 0) and `scope` (`ascent` or `full`). Poll the returned job ID and use
`GET /api/exports/{export_job_id}/download` when complete. The old direct
`GET /api/predictions/{job_id}/sonde.nc` URL remains available for scripts and
profile pop-outs. The sonde's 22 variables, dtypes and sampling method are
unchanged. Export source receipts and storage leases remain enforced.

## Floating, tiling, maximise and alignment

**Dock** is replaced by **Arrange ▾**, whose choices say what they do:

- Left/right/top/bottom half and each corner quarter.
- Maximise, Float window, and (for Map/Details) Stack Map & Details.

Drag an unlocked panel toward the edges of the **Trajectory workspace**:

- Left/right edge → corresponding half.
- Corners → corresponding quarter.
- Top edge away from the corners → maximise.
- Bottom edge away from the corners → bottom half.

An orange preview shows the destination before release. Placement is bounded by
the workspace, not the whole browser/monitor. Tiled panels adapt when the
workspace resizes. Drag a tiled or maximised panel away to return to floating
geometry. Overlapping other windows is allowed; tiling one window does not
silently move or close another one.

Moving and resizing edges gently align with nearby panel/workspace edges. The
alignment releases when you pull a little farther, so windows can cross freely.
Hold **Alt while dragging/resizing** to bypass alignment and edge tiling entirely.
Locks prevent gesture movement/resizing; explicit Arrange commands still work.

**+** maximises. Its replacement is a two-box restore symbol whose tooltip and
accessible name read **Unmaximise**. Restore preserves the prior panel geometry,
placement and visibility. Double-click a header to maximise/unmaximise.
**−** minimises; toolbar buttons toggle minimise/restore. Arrow keys on an
unlocked header move it (Shift = larger steps). Alt+Arrow keys tile it. The
bottom-right resize control also supports arrow keys. Arrange menus support
arrow keys, Home/End and Escape.

Map and Details can still share a draggable split when stacked. Unlock both to
resize the separator; Up/Down also adjusts it. **Reset layout** restores defaults.
v1.3 geometry/locks migrate into v1.4; saved launch setups keep their existing
storage key. Export caches are per-session selection state, not launch setups.

## Verification and limits

- 89 backend tests pass, including the new sonde job, repeat downloads, selected
  series flight, source replacement rejection, input validation, and ascent-only
  landing validation. The existing 82 v1.3 tests remain in the suite.
- The actual frontend JS passes its existing DOM/API workflow regression.
- A separate window interaction check passes 13 scenarios for pointer tiling,
  magnets/release, offsets, menus, locks, restore, resize, mobile and migration.
- The export/loading DOM/API check creates real NetCDF files from a synthetic
  grid and verifies independent cards/scopes, selection changes during jobs,
  automatic download/save links, whole plans, errors/retry and loader cleanup.

These checks exercise code and API responses; they do not render CSS. A local
Chromium/Firefox browser could not start in this execution runtime, and the
remote browser could not reach its local test server. Rendered desktop/Android
appearance and actual touch behaviour are therefore **not claimed as tested**.
The included Playwright regression is updated for this interface and can run
locally. Windows/PowerShell startup was reviewed, not executed here.

Developer checks (normal use does not require Node):

```bash
python -m pip install 'pytest>=8,<10' 'httpx>=0.27,<1'
python -m pytest
npm install
npm run test:ui
npx playwright install chromium
npm run test:browser
```

Use `BP_TEST_PYTHON` for your environment's Python if it is outside `.venv`, and
`BP_TEST_TMP` for a writable temporary directory when needed.

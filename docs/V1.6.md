# BalloonPredictor v1.6

Version 1.6.0 updates flight profiles, panel arrangement, launch protection,
weather selection and the installed apps' connection dashboard. The prediction
engine, per-account storage and v1.5.3 browser login remain available.

## Flight Profile

Both plots now use the same **logarithmic pressure scale**, with pressure on the
left and **altitude in km AMSL on the right**. Their vertical ranges and pressure
rows match initially. The right-hand altitude ticks are interpolated from the
actual sampled model pressure/height pairs, rather than a standard-atmosphere
conversion. Altitudes outside those samples are not invented.

The Skew-T uses a 45-degree temperature skew in display coordinates and preserves
the existing orange temperature and green dew-point lines. Its dry adiabats,
liquid-saturated pseudo-adiabats and mixing-ratio guides use the same pressure
transformation. The initial view fits the available sounding instead of forcing
a shallow flight into an almost empty whole-atmosphere plot.

Conventional wind barbs appear to the right of its altitude axis. Speeds are
converted from model m/s to **knots**: a short feather is 5 kt, a long feather is
10 kt and a triangular flag is 50 kt. Calm wind is a small circle. Samples are
thinned vertically to keep the barbs readable, and a hover title gives the
pressure, speed and direction. The separate blue u / purple v plot is retained.

Each plot supports:

- Mouse-wheel and two-finger pinch zoom.
- Dragging to pan, with arrow keys as a keyboard alternative.
- Plus/minus buttons and keyboard +/- for zoom.
- Reset, double-click or keyboard 0/Home to restore the initial view.

**Link vertical zoom** starts enabled: vertical zoom/pan follows between the
plots while their horizontal temperature/wind ranges remain independent. Untick
it to explore each plot separately. Re-enabling it aligns the wind plot to the
current Skew-T pressure range. The separate-window view has the same controls;
its SVG download follows the current view. At narrow widths the plots stack
vertically to remain readable.

These are synthetic model soundings, without parcel/CAPE/CIN or sensor-response
calculations. Missing humidity still produces no dew-point trace. The liquid
water approximations used for dew point and saturated guides remain labelled.
The mathematical conventions were checked against the
[MetPy SkewT documentation](https://unidata.github.io/MetPy/latest/api/generated/metpy.plots.SkewT.html),
its [moist-lapse equation/example](https://unidata.github.io/MetPy/latest/api/generated/metpy.calc.moist_lapse.html),
and [Matplotlib's barb convention](https://matplotlib.org/stable/api/_as_gen/matplotlib.pyplot.barbs.html).
No new runtime plotting package or external chart service is required.

## Arrange panels together

Choosing **Arrange → Right half** for Flight Profile puts it on the right and
places the other two open, unlocked windows in the top-left/bottom-left quarters.
With one other open window, that window occupies the left half. Left, top,
bottom and corner arrangements follow the same idea; dragging to an edge uses
the same coordinated layout.

Shared separators resize the adjoining windows together. In the example above,
the vertical divider changes the left/right ratio, and the divider inside the
left column changes the Map/Details ratio. The handles can also be focused and
moved with arrow keys. Locking adjoining panels disables that shared divider.

Locked other windows retain their position. Unlock them before arranging if you
want them included in the layout. A window can still be dragged away to float,
freely resized or maximised. Minimise collapses its tiled space until it returns.
Reset layout restores the familiar Map/Details stack. Saved v1.4–v1.5 layouts
remain readable, and new divider ratios are saved with the existing layout.

## Launch and sensitivity safeguards

A map click or launch-marker drag now asks before moving a launch point which
has a calculation, series or active job. **Keep current location** or Escape
retains the launch and its tracks. **Move & clear these tracks** clears only the
selected launch point; other points are retained. Placing an uncalculated launch
remains a direct map action.

Sensitivity dots/region is disabled while no displayed flight has sensitivity
members. It becomes available when any launch has members, including when the
active launch itself has none. The geographic region retains its fixed margin
and includes the nominal endpoint. A single member can form a rounded region
with the nominal endpoint; an empty ensemble does not produce a region.

## Weather dataset and run

Flight Setup now separates **Weather dataset** (ERA5, ERA5T, WRF, ECMWF IFS, GFS,
other files or Demo) from **Run / saved forecast** immediately beside it.
Runs are ordered newest first by forecast cycle or WRF initialization time,
with time coverage and labels used where those fields are unavailable.
Domain/box names distinguish multiple files from the same cycle.

Demo and a single ERA5 archive do not show a meaningless run choice. If several
ERA5 subsets were downloaded, an **Archive / saved subset** selector preserves
access to those files. ERA5's archive-day control still follows the launch date.
The IFS/GFS run lists retain an option to download a new forecast. Existing saved
setups and shared links still refer to the exact dataset ID, and switching launch
points restores the saved model and run.

## Connection dashboard

Local and Server choices use equal-height white cards, rounded coloured icon
badges, a clear selected outline/check and consistent typography. Android no
longer baseline-aligns unequal multiline buttons, which caused the offset.
The original explanation about choosing a device/server and retaining the live
flight is kept. Windows, Mac and Debian use the same card styling in their
connection screen. Local/Server behavior, VPN prompts, SSH authentication,
browser sign-in and Return to flight are retained.

### Android without a connection

Local mode still calculates on the phone from a saved `.bpforecast` file. Save a
regional pack while connected, then open it in Local mode before leaving signal
coverage. The Android app does not bundle the desktop Python/NetCDF engine.

## Run on your server

The default remains **8005**. Stop the previous process on that port, extract the
new source on /data1, then run it under the same Unix service account:

```bash
bash start-shared-server.sh
```

Open `http://YOUR-SERVER:8005` over your VPN and use the normal login page. Personal
data remains at `/data1/tim/BP_Data/<verified Unix username>/`. The existing
`.server-8005/config.yml`, data-volume environment and downloaded files are
retained. Service output is in `/data1/tim/BP_Data/.server-8005/server.log` and
each account's job log is in its own `logs/balloon-predictor.log`.

The shared-server guide [V1.5.3.md](V1.5.3.md) covers first-time migration and
nonstandard local SSH settings. Other computers keep their normal per-user
storage or chosen custom data directory. No personal home directory is hardcoded.

## Prepare and publish

The kit contains the complete source, `prepare-v1.6.0.sh`, `release-v1.6.0.sh`
and START-HERE.md. Prepare uses a temporary checkout and works from the existing
Git repository even while main remains an earlier version. It builds on the
public v1.5.3 test branch and pushes `release-v1.6.0-test`.

All five workflow checks must pass for the same commit before release. The
release helper identifies workflows by **file path**, so the earlier Python
workflow display-name mismatch does not prevent release. It verifies checksums,
build metadata and both Mac installation reports. It creates a **draft** by
default; only `--publish` advances main and publishes the release.

Keep the existing Android signing key. Signing setup now defaults to a local
`~/.config/balloon-predictor/android-signing` folder, respecting XDG_CONFIG_HOME or
BP_SIGNING_DIR. It retains keys already configured on GitHub. This is separate
from the server's weather-data storage and does not involve Google Play.

Windows x64, universal Mac (macOS 15+, Intel and Apple silicon), Debian 12+ amd64,
and Android 8+ installers retain their native Actions build/install tests.
The kit's VALIDATION.json records the completed local tests and the native checks
which still need GitHub Actions. Do not treat a local APK compilation as an
Android emulator or physical-device test.

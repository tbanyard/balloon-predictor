# BalloonPredictor v1.6.3

The shared server now defaults to **port 8008**. Existing storage, browser sign-in,
SSH identity checks and per-user workspaces are unchanged.

Dates and UTC times have separate editable boxes. Use the calendar button beside
the date or type a date as YYYY-MM-DD and a 24-hour time. Launch and arrival times
accept seconds; downloads use whole minutes and model cycles use whole hours.
The same controls work in browsers and installed desktop/Android views.

Opening Connection/Server settings on Windows, Mac and Debian keeps the flight
page loaded separately. Return to flight restores its calculated tracks, chosen
flight, plots and map position. Selecting a new connection opens that connection.
Android retains its existing return-to-flight behaviour.

Click a track or its endpoint to inspect that flight. Tracks have a wider click
area without becoming thicker on the map. A small flight list resolves overlapping
tracks. These clicks do not move the launch point. Flight Details buttons remain
available as an alternative.

An open Flight Profile renders the first completed flight automatically, including
after editing and recalculating a series. Resizing a panel does not reset an
already rendered profile's zoom. Android Local/Server cards have lighter, consistent
shadows without the default button elevation animation.

Use the kit's START-HERE.md for server and prepare/release commands. New installer
binaries are produced by the five GitHub workflows; old successful runs cannot
validate this source. Android retains its offline .bpforecast calculator.

## Installer build repair

The Windows shell starts its retained flight WebView on a real local page.
An initial about:blank navigation can fail to emit WebView2's page-loaded event;
waiting for it prevented the connection screen from appearing. Per-view startup
logging now identifies which page is still loading. Flight retention is unchanged.

Android builds reuse checksum-verified JARs from the GitHub Actions cache and use
Google's hosted Maven Central mirror with Central as a fallback. Transient errors
have a maximum of three attempts, delayed retries and Retry-After handling.
Incomplete downloads are removed and checksum failures stop immediately. Verified
downloads are saved even when a subsequent build or emulator step fails. No signing
keys are stored in the dependency cache; existing Android signing secrets remain
in use. A continuing upstream outage can still require rerunning the workflow.

A Mac job reporting that no hosted runner acquired it has not executed the build.
Rerun the failed jobs on the same source commit. The release verifier still needs
all five successful workflows for that commit.

Mirror documentation: https://docs.cloud.google.com/docs/buildpacks/java

# BalloonPredictor v1.5.3

Open the shared server in a browser and sign in with your normal server username
and password. The new login page replaces the command and 60-second link from
v1.5.2. Your personal data stays in:

```text
/data1/tim/BP_Data/<verified Unix username>/
```

## Start or upgrade the shared server

Stop the previous server on **8005** first. From this version's source directory,
using Python 3.12 or newer:

```bash
bash start-shared-server.sh
```

The default web port is now **8005** throughout the launchers, app connection
forms and current documentation. The explicit equivalent is:

```bash
bash start-shared-server.sh --port 8005
```

Open `http://YOUR-SERVER:8005` using the VPN as usual. Enter your own server
username and password. If the SSH service asks for a verification code or other
sign-in response, the page displays that question. Each person uses the same
address; nobody needs a personal port, a terminal command or a timed link.

Keep this password login behind your trusted VPN, or serve it through HTTPS.
SSH protects the server-side authentication connection; an ordinary HTTP page
itself does not encrypt the connection from the browser to the web server.

If you already ran v1.5.2 on 8005, the launcher reuses
`/data1/tim/BP_Data/.server-8005/config.yml` and the existing personal folders.
It does not recopy an already recorded migration or replace existing data. Keep
running it as the same Unix service account. A server restart requires everyone
to sign in again; saved flights and downloads remain available.

For a first migration from an older setup, custom paths can be supplied:

```bash
bash start-shared-server.sh \
  --config /path/to/previous/config.yml \
  --source /path/to/previous/data
```

The launcher copies and verifies the operator's old files without deleting the
source. Existing external ERA5/WRF archives remain available for reading. Other
users get their own downloads and predictions. If an existing destination has
no migration receipt and you want to retain it without importing old files,
add `--fresh`. Use `--shared-root /path/to/BP_Data` for another data volume.

The virtual environment, pip cache, temporary files and service output stay
under `/data1/tim/BP_Data/.server-8005/`, outside the home quota. The launcher
checks for a running service on the selected port before installing packages.
Do not run a second process on the same port.

## Sign-in and personal folders

The web server checks credentials against its own SSH service on 127.0.0.1.
It verifies that service's public host key using the local SSH public-key files.
The authenticated SSH process then contacts the existing Unix identity broker.
The kernel-verified Unix account selects the data folder; a typed username,
URL parameter or HTTP header cannot choose someone else's workspace.

Passwords and verification-code responses are used for the current sign-in and
are not saved to files, browser storage or application logs. Sign-in attempts
are limited, can be cancelled, and allow up to ten minutes for an interactive
question. The page performs the short-lived internal handoff automatically;
there is no link for a person to race to open.

The browser session uses an HttpOnly, SameSite cookie, with Secure enabled on
HTTPS. It expires after twelve hours of inactivity or a service restart.
Choose **Manage weather → Sign out** to end the browser session. If it expires,
the next API request returns you to the login page.

The service account owns each private workspace, as in v1.5.2. Keep individual
folders private; do not chmod them to 777. Every SSH account needs directory
traversal permission on `/data1/tim` and the parent path. The shared root's
sticky bit protects its entries when the root is world-writable.

## SSH settings, if your server differs

The default SSH port used by browser login is **22**, separate from the web
application's **8005**. Normally no extra configuration is required. If local
SSH uses another port, edit the existing server config:

```yaml
web_login_ssh_port: 22
```

The defaults read `/etc/ssh/ssh_host_ed25519_key.pub`,
`/etc/ssh/ssh_host_ecdsa_key.pub` and `/etc/ssh/ssh_host_rsa_key.pub`. If your SSH
host public key is elsewhere or unreadable to the service, set its public file:

```yaml
web_login_host_key_file: /path/to/ssh_host_ed25519_key.pub
```

Use the **public** `.pub` file, never the private host key. Equivalent environment
overrides are `BP_WEB_LOGIN_SSH_PORT` and `BP_WEB_LOGIN_HOST_KEY_FILE`. Restart the
service after changing them. Local SSH must allow these accounts to authenticate
with a password or keyboard-interactive prompt and run the existing Python 3
identity helper. A key-only account can still use the advanced manual helper
after its usual SSH sign-in. The old helper remains for compatibility, rather
than being part of the normal browser workflow.

## Installed apps

Windows, macOS, Debian and Android retain the large **Local** and **Server**
choices. Choose **Server → SSH tunnel** to use the established app login and
automatic workspace handoff. Use web port **8005**; the SSH port is usually 22.
Saved connection preferences are retained, so change an old saved 8004 value
once if necessary. Opening Server settings and returning retains the live flight.

**Web server** mode can now open this version's browser login page too. An older
shared server without browser login still requires the SSH tunnel option.
The desktop app's internal loopback port stays unchanged so saved local sessions
keep the same origin. It is separate from the remote server's 8005 setting.

Choose **Local** for the desktop app's full local Python engine.

### Android without a connection

Android's Local option retains its offline forecast-pack calculator; it does
not bundle the desktop Python/NetCDF engine. While connected, save a regional
`.bpforecast` file, then open it in Local mode before leaving signal coverage.

## Storage and logs

Manage weather shows your username, active data folder, job log and storage
health. The service output is in:

```text
/data1/tim/BP_Data/.server-8005/server.log
```

Each person's job log is in:

```text
/data1/tim/BP_Data/<username>/logs/balloon-predictor.log
```

The storage and terrain improvements from v1.5.2 remain. Missing physical DEM
tiles still require the missing-tile download action; changing storage cannot
provide absent terrain. Standalone installations retain their own data-folder
selection and normal per-user paths. The shared root remains operator-managed.

## GitHub packages and validation

The kit's START-HERE.md gives the prepare and release commands. The prepare script
includes v1.5.2 and v1.5.3 together and works even if your normal checkout is
still on v1.4. It uses a temporary checkout and pushes `release-v1.5.3-test`;
your working files and main are preserved during preparation.

The five Actions workflows check Python/browser behavior, Windows x64, universal
macOS (Intel and Apple silicon, macOS 15+), Debian 12+ amd64 and Android 8+.
Browser regressions exercise real SSH password authentication, rejected passwords,
verification codes, logout, automatic app reconnects and account isolation.
The complete SSH-to-Unix-broker handoff is required in Linux CI as well.

The release script accepts only successful workflows for the same source commit,
verifies installer checksums and source metadata, and requires both installed
Mac test reports. It creates a draft by default. `--publish` fast-forwards main
and publishes the tested binaries and exact source ZIP. Native installed-app
tests must pass in GitHub Actions; local source tests or APK compilation alone
do not establish compatibility with every device.

Keep your existing Android signing key. `setup-android-signing.sh` retains a key
already configured in the repository; Google Play is not involved. Windows/Mac
signing and notarization status is unchanged. The kit's VALIDATION.json records
what was tested locally and which native checks still need Actions.
